# 职业背景与卡点输入

输入分为三组，已有信息不重复询问：

| 输入组 | 用户提供什么 |
|---|---|
| 职业背景 | 当前身份、学历/专业或工作经历、主要职责 |
| 职业卡点 | 校招/社招/瓶颈/Offer/跳槽场景，最想解决的问题 |
| 自己的八字 | 年柱、月柱、日柱、时柱，或清晰排盘截图 |

首轮可直接说：
“请告诉我：①你的职业背景；②现在最想解决的职业卡点；③你的八字四柱（按年、月、日、时排列），也可以发排盘截图。没有现成八字的话，提供出生日期、时间和城市，我再辅助排盘。已有的信息不用重复。”

下一轮补齐目标城市、薪资、工作方式和期限。直接四柱不强制补交出生资料；仅在需要辅助排盘时补齐日期历法、时间精度和当时时区。将未回答项记为未知。

推荐排盘项目：[6tail/lunar-python](https://github.com/6tail/lunar-python)。它是 MIT 许可的开源历法库，支持四柱和十神计算。本项目的本地排盘脚本已使用它。已有四柱或排盘截图可直接提交；没有现成命盘时，提供出生资料，由 Skill 调用本地脚本辅助排盘，并注明计算口径。

## 可选简历与亮点补充

邀请用户提交简历附件或摘录，也可以口述。先复用简历已有信息，再问一件用户自己觉得做得好的事。以用户愿意分享的程度为准。

## 八字输入确认

- 文字四柱：复述顺序，检查每柱为有效干支组合；缺失或有冲突先问清楚。
- 截图：先识别、展示四柱供核对；看不清的字不要猜。截图与文字冲突时由用户澄清。
- 没有命盘：走出生资料排盘流程，不把生日误称为已输入的八字。
- 未收到或未能读清八字时，先完成输入收集，不生成八字解读和基于该盘的方向；用户明确希望先看现实建议时可单独进行。

## 场景补充

| 场景 | 必要补充 | 可接受的低门槛输入 |
|---|---|---|
| 校招 | 毕业时间、专业/学历、实习项目、校招资格、城市与求职期限 | 没有实习可以用课程/社团/个人项目 |
| 社招 | 工作年限、职责、两个成果、已投岗位与反馈 | 无简历也可口述 |
| 职业瓶颈 | 卡住多久、最近实例、已经尝试什么、可控制因素 | 一个具体事件即可开始 |
| Offer选择 | 至少两个选择及条款、个人优先级、决定期限 | 匿名A/B，敏感字段可删 |
| 跳槽转型 | 留任选项、转型动机、可迁移成果、学习时间、财务缓冲范围 | 缓冲可选“1月以内/1–3月/3–6月/更长/不透露” |

## 结构化工作记录

记录 scenario、background、blocker、desired_outcome、deadline、skills_evidence、constraints、chart_input_type（四柱/截图/出生资料）、pillars、chart_source、chart_verification_status、birth_precision（仅出生资料入口）、unknowns。出生资料保留在当前对话，不写进搜索计划、代码仓库、日志或示例。用户要求保存报告时先去除不必要出生细节；完整出生资料仅在用户明确要求时加入。

## 追问规则

把“你擅长什么”换成“最近哪件事你做得比同事轻松，而且有结果？”
把“你不喜欢什么”换成“哪类任务即使做得好，也让你持续消耗？”
把“想要什么职业”换成“未来一年，收入、稳定、成长、自主、意义感中最重要的两项是什么？”
不要诱导用户提供符合命理解释的经历；同样询问反例。
